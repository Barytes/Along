网络效应说的是：一个人使用某样东西得到的价值，取决于还有谁在用，而不只取决于这件东西单独有多好。智能体这边，真正能形成网络效应的单位不是「又多了一个 agent 人格」，而是又多了一个人的信息孤岛，并且下一次关键调用因此拿到了更完整、选对了、且有资格被当作依据的内容。到达、选用、保真分别打断的是「连得上」「连对了」「连上来的东西能用」；这三处断了，人再多也只是更多孤岛，或者变成负的网络效应。前沿实验室里的大规模集群是另一件事：同一条信任边界里的并行和编排。有网络效应的智能体能在跨孤岛任务上接近、甚至超过实验室集群，因为实验室并没有别人的私人信息；它不能在密集协作和全量互见上追上实验室，因为那种密度靠的是把孤岛先拆掉。

## 网络效应是什么，以及它如何表现出来

网络效应是一种价值随参与者增加而变化的性质。一个参与者从产品里得到的好处，是其他参与者（或因他们而来的互补品）的函数。电话是直接网络效应：能打通的人越多，这部电话越有用。应用商店是间接网络效应：一边的用户多了，另一边的开发者更愿意来，应用多了又让用户更愿意留下。本地网络效应把「谁」收窄到你在意的那一群人：Slack 对一个五人小组的价值，取决于这五个人在不在，不取决于全球有多少工作区。兼容性网络效应出现在格式和协议上：别人都用同一套接口，你也必须用，否则交不了文件、接不上工具。数据网络效应指的是：更多使用留下更多可复用的记录，这些记录让后来的使用更好；它只有在新记录真的提高后来调用的质量时才成立，人多、字多本身不算。

网络效应在市场上的表现是一组可以观察的行为，不是一句「越多越好」。新产品启动时会碰到冷启动：前几个用户几乎得不到网络带来的价值，所以不愿加入。一旦同一群需要彼此协作的人进来了，后来的人加入的理由变成「对方已经在这里」，而不是功能清单更长。离开的成本上升，因为你的协作对象、历史记录和互补工具都在这个网络上。互补品会围着这个网络长出来：技能、连接器、审查流程、计费和审计，都因为已有参与者才值得做。竞争往往变成少数网络占住各自的协作圈，后做的同类产品即使单机功能更强，也搬不走已经互相依赖的那群人。

网络效应也可以是负的。新参与者让拥堵、垃圾信息和低质量内容上升，以至于后来的人得到的价值下降。道路在车多时变慢。邮件在谁都能群发时变脏。交易市场在劣质卖家涌入时，好买家离开。判断一个系统有没有网络效应，要看新增一个参与者之后，原有参与者的下一次使用是变好还是变差。只看注册人数，分不清正的网络效应和规模不经济。

## 智能体的网络效应应当是什么样

智能体的网络效应不应当定义成「agent 互相通话的次数」或「同时在线的 agent 个数」。Jean-Denis Greze 在 2026 年 9 月的演讲里把「agent-to-agent 会产生很大的网络效应」这句话拆开了。人本来就和其他人一起工作，协作的人越多，能做完的事越多，这是对的。把这件事说成「多智能体」并不成立。理想状态是一个能看见全部信息的 agent，只做一次关键的 LLM 调用，上下文里已经有正确信息。世界上有许多 agent，只是因为隐私和安全不允许任何人拥有一个随时查看所有邮件、所有公司记录的通用 agent。评价标准因此是：系统在多大程度上逼近「那一次调用里已经有完美系统会用到的那些数据」。真正重要的不是人格数量，是那一次调用的上下文。

按这个标准，智能体网络的节点是人和他们的信息孤岛，以及接在这些孤岛上的工具。一条正的网络效应应当写成：网络上每多一个人和他的孤岛，其他已经在网上的人，下一次让自己的 agent 做事时，窗口里会多出一份以前到不了的、选对了口径的、并且有资格被当成依据的内容。价值加在那一次调用上，不是加在「又多了一个会聊天的机器人」上。

这种网络效应有三种彼此不能互相替换的形态。第一种是本地的直接网络效应：你的同事把他的有用经验留在网络能取到的位置，你的 agent 不必再问他、也不必再做一遍。五人小组里进来第六个做过同类部署的人，前五个人的 agent 当天就应当少踩一个坑。第二种是跨边的间接网络效应：用的人多了，才有人愿意把仓库、数仓、工单、审查流程接到这个网络上；工具多了，下一次任务能取到的材料更完整。第三种是数据网络效应：每一次被选对、并且事后证明可用的调用，留下适用边界和来源，让后来的路由更准。第三种最容易被假冒：agent 自动写下的频道记忆、wiki 摘要、会议纪要，字数在涨，后来的调用却更差，那是负的数据网络效应。

假的智能体网络效应长得像网络，加进去的却不是可连接的孤岛。同一次任务里再拉起二十个子代理，是并行和编排，价值来自算力和拆分，不来自「又一个人加入了网络」。同一个 Slack 工作区里消息变多，检索面变大，也可能只是噪音变大。一万家公司各自装了同一款聊天机器人，但彼此的经验到不了对方的那一次调用，这是分发，不是网络效应。Claude Tag 在 Anthropic 产品团队里写出 65% 的代码，证明的是：在同一家公司、讨论已经在 Slack、仓库已经接到频道的前提下，共享一个可被 @ 的 Claude 能把活做完。它证明的是信任边界内的到达被减轻了，不是任意两个陌生人的 agent 已经形成了网络。

智能体网络要成立，新增的那个人必须同时满足三件事。他的有用经验能到达别人的那一次调用。到达之后，生效的是适用于眼前这个对象的那一份理解，而不是把他的习惯盖到所有人头上。留下来的内容有资格被当成依据，而不是一句写得很确定、没人判断过对错的话。少一件，网络的边是断的，或者边是毒的。

## 三个问题分别挡住了哪一条边

到达问题让新节点加不进可被调用的图。对当前任务有用的经验已经存在于某台电脑、某个仓库、某次组会或某个已经离开的人那里，但进不了这次正在工作的 agent，或者送进去的成本高于再做一遍。网络效应要求：第六个人加入后，前五个人的下一次调用能用到他已经有的经验。到达失败时，图上多了一个点，没有多一条边。第 1 条里两位创始人各跑本地 agent，策略和客户笔记堆在本机，对方提问要从零开始，人从两个变成三个不会让任何一个 agent 变强。第 3 条里 A 仓库的部署约束进不了 B 仓库，仓库数增加只是孤岛数增加。第 5 条里学生毕业，判断跟着人离开，网络的节点在减少，不是在增值。协作软件上的智能体把边限制在已经写进频道、文档和工单的那一层：本机上的 Skill、私人笔记、未连接的仓库仍然不是边。Jean-Denis 讲的第四种做法——向所有人发 Slack 请求、请每个人批准查看自己的信息——是到达成本高到用广播代替选择。人越多，通知越多，负的拥堵和正的网络效应同时出现，前者通常先被感觉到。

选用问题让新节点加上去之后，旧节点的调用变差。对同一对象已经存在多份不一致的理解，这些理解能够被看见，但这一次该生效的是哪一份没有定下来。网络效应要求：分析师 B 加入后，场景 B 里的 query 变准，场景 A 里的 query 不变差。选用失败时，B 的 Skill 被写进同一份基础 YAML 或同一条工作区记忆，A 的有效 join 被覆盖，或者两套口径一起塞进窗口，模型报出一个对当前问题作废的数字。这时每多一个人，冲突组合就多一截，后来者在伤害先来者。这是典型的负网络效应，和劣质卖家涌进市场是同一类机制。第 2 条里 1 到 2 人还能口头对齐，人一多，指标定义和常用表开始冲突，agent query 出现偏差：网络变大的时刻，正好是价值下降的时刻。OpenViking 那通赔付电话里三份正式材料都在，检索也有了，人越多、文档越多，引用越完整，眼前这个客户该用哪一条却越不清楚。公开频道里任何人都能改 Claude Tag 的工作区记忆，后写入的那一句会对全工作区生效，这是用「谁最后说了一次」代替路由。实验室里的智能体还有一层更厉害的负效应：模型在相同上下文里动作方差低，许多 agent 会把同一套错口径写成同一句很确定的话，错法相关，传播比人类各写各的更快。

保真问题让网络上积累的边失去当依据的资格。内容已经被写下并可能被检索到，但事实是错的、只留下了结论，或不能代替这一次的判断。数据网络效应要求：每一次使用留下的记录，让下一次调用更好。保真失败时，每一次使用留下更多可被引用的确定错误。第 4 条里没有人看过的 agent 条目坏得最快，错误条目被别的 agent 引用，写得很确定的错误越来越多：这是负的数据网络效应已经发生。第 3 条后半，「收入不算退款」完整写在 `CLAUDE.md` 里，做决定的人当时可以没想过什么情况下这样算会错；这句话随后成为全网络可检索的「决定」。第 5 条第 1 点，论文和笔记存得越多，找方向仍然要人重新判断；网络变厚，判断没有被完成。协作软件把自动记忆当成功能：Claude Tag 在工作中自己记下频道决定，Notion 和飞书的代理把答案回写进知识库。写得越容易，没有资格的边越多。人若用「每周回顾记忆」把关，审查成本随网络增大而增大，到达问题里想省下的时间又回来；人若不管，网络越大越不能用。

三件事可以同时成立，而且会互相放大。到达被做成全量共享之后，选用冲突和保真错误进入公共层的速度加快。选用被做成强行合并之后，错误口径成为全网唯一依据，保真失败被锁死。保真靠人审把关之后，没人愿意再交东西出去，到达重新失败。所以这三个问题不是网络效应旁边的三个产品细节，它们就是网络的边能不能增值。

## 真的形成网络效应之后，人会怎样用

形成网络效应之后，人主要不再为「把东西交给别人的 agent」本身工作。任务开始时，自己的 agent 已经带着这一次需要的、可以给它看的那一小段跨人内容。用户不会先开一轮「我们公司定价怎么定的」「这个指标包不包括退款」「上次竞品分析在哪」。这些话仍然可以问，但问的时候答案已经在窗口里，而且带着它来自谁、适用于什么条件。使用方式从「打开一个聊天窗口，从头解释公司」变成「在自己原来的编辑器、仓库、频道里继续做事，网络在调用发生前把该到的东西送到」。

典型用例按已经出现过的工作写，而不是按科幻写。

双人创业里，Alice 的 agent 在本机发现了定价约定。Bob 第二天问同一件事，他的 agent 在不读 Alice 私人笔记和半成品判断的前提下答对。两人同时改共享的定价说明时，冲突能追溯到作者，错误晋升可以撤销。Bob 不会收到「请批准我阅读 Alice 的全部文件」这类广播。网络的表现是：Alice 还在网上这件事本身，让 Bob 少做了一次从零解释。

分析师写 SQL 时，基础表结构来自公认层，这一次该用的 join 和指标定义来自与当前业务问题匹配的那一份个人 Skill。分析师 A 的习惯继续在场景 A 里生效，不会因为 B 加入就被合并掉。query 跑出来的结果和已声明口径下的标准查询一致；没有声明时，系统同时给出两套定义，而不是假装只有一套。网络的表现是：B 的加入让场景 B 变准，场景 A 没有变差。

数据工程里，仓库 A 的 agent 学到「部署必须跑 X」并晋升到组织层。仓库 B 里做相关任务的 agent 检索到 X，且「我喜欢 verbose log」这类个人偏好没有进去。晋升走可审的 diff，不是频道记忆里一句无人看过的话。网络的表现是：A 仓库还在被使用，B 仓库的 agent 不必重教。

事故处理里，值班的人在频道里说现象。agent 拿到的是上一次相近事故里已经核对过的处置步骤，带来源和「什么情况下这样处理会错」。它拿不到一篇写得很确定、没有人看过、由另一个 agent 根据会议录音整理的错误摘要。网络的表现是：过去的值班还在网上，这一次的窗口更干净，不是更长。

课题组里，新生开题时取到的是已经比较稳定的方法和说法；导师看同一套材料时取到的是空白和张力。毕业的师兄留下的试错记录到得了后来课题的起点，私人情绪和未完成的猜测没有到。找方向仍然要人读、要人判断；网络送来的是判断需要的材料位置和分歧，不是一句「这个方向值得做」。

跨公司的用例目前最少，也最接近 Jean-Denis 说自己没有答案的那一段。贷款场景里，多家投资银行各自有未上市公司的私有数据，分享其中一部分对放贷有收益。网络若形成，银行的 agent 在对方同意的范围内取到这一次放贷需要的字段，过程可审计，未授权的字段不到窗口里。没有形成时，要么谁都不肯接，要么接上之后一次错误披露就结束合作。这类用例一旦跑通，才是跨信任边界的网络效应，而不只是公司内部的共享频道。

日常操作看起来会像现在的 `@Claude`、`@Linear`、飞书群机器人，产品却不应当是「再 @ 一次」。人继续在 Slack、仓库、文档里说话。agent 在发起工具调用之前，已经从网络上取到最小的那一组跨孤岛内容。需要人的时刻变成两件：选用上两套口径都说得通，必须由人指定眼前这个对象听哪一套；保真上内容要离开低敏感区，必须由人确认它有资格进入公共层。到达不再占用会议和传文件。Jean-Denis 说的黑箱做法如果被接受，查找发生在无人值守的调用里，只向真正拥有答案的那一个人征求「可不可以把这一点分享出去」。频道不会因为每一次检索就被刷满批准请求。

人能从表面上判断网络效应已经形成的信号有三条。新成员的 agent 在第一周就能完成老成员上周在做的同类任务，而且老成员没有专门给它写过一份入职文档。网络变大之后，同一句业务问题的错误率下降，而不是引用变多、对错更难说。有人离开时，他的私人内容可以带走或关闭，他已经晋升且仍有资格的那一部分继续为留下的人工作。做不到这三条，只是又多装了几个频道机器人。

## 这样的网络能不能逼近前沿实验室里的大规模集群

前沿实验室里的大规模智能体集群，是同一条信任边界之内的并行、委派和监控。Anthropic 在 2026 年 8 月的测量里写明：最常用的内部平台上，任意时刻大约有 3 万个 agent 在做研究和工程；这些动作在执行前全部经过在线监控，执行后全部进入离线监控；Claude「主导」约 26% 的 AI 研发工作，90% 以上至少是人与 Claude 协作。Claude Code 的子代理和 agent teams、Codex 的委派并行、Kimi 的 Agent Swarm，以及把组织智能扩到 1024 个 agent 的 Agensh，用的都是编排器拆任务、工人并行、结果再汇总，或工人在同一套工作流指令下自组织。它们共享公司代码、内部数据、统一的监控和同一套模型。评价标准是吞吐、覆盖率和事故率，不是「又一家外部公司加入之后，内部这 3 万个 agent 的下一次调用是否变好」。

这和网络效应不是同一条轴。实验室集群回答的是：在几乎已经能互相看见的前提下，如何同时跑很多 agent，并把它们的动作管住。网络效应回答的是：在不能互相看见的前提下，如何让多一个人让别人的那一次调用变好。Jean-Denis 的理想——一个能看见全部信息的 agent——实验室在公司内部更接近，因为信任边界已经被雇工合同和内网拆掉了很大一块。策略一说的「在一条信任边界内近似获得全部访问权限」，描述的就是实验室和大型公司正在做的事。它不会随着模型变强自动打通原来的孤岛，它只是因为某个人做了一个决定，又造出一座新的孤岛。3 万个内部 agent 可以把这座孤岛利用到极限，不能因此变成跨公司的网络。

实验室集群甚至说明，只增加 agent 个数也不等于协作变好。Anthropic 在 2026 年 8 月的多智能体研究里写过：agent 把彼此当工具调用时还可以；把彼此当长期平等的同伴、没有明确层级时，协调仍然差。45 个 agent 的漏洞扫描在任务可并行、彼此不太互相依赖时有用。让若干 swarm 共同做一个互相关联的游戏时，产品仍然差；较老的模型合并不了互相冲突的 pull request，较新的模型用「尽量不改别人的文件」躲开冲突，只有个别模型又能共享代码又能保持合并吞吐。目标矛盾时，三个 Claude Code 实例会把对方当成障碍，互相破坏。动作方差低时，许多 agent 起同一个分支名、写同一篇题目的小说、同时用同一套高频率轮询把队列打满。这些失败发生在已经共享虚拟机论坛和代码仓库的集群里。跨孤岛的网络如果只模仿「多拉起一些 agent 让它们互相说话」，会把这些失败再加一层到达和隐私约束，不会更接近实验室。

有网络效应的智能体在一类任务上可以逼近、并在信息范围上超过实验室集群。这类任务依赖的是分散在不同人、不同仓库、不同公司里的经验，而实验室内部并没有这些经验。定价约定在联合创始人的本机上，指标口径在分析师各自的 Skill 里，部署约束在另一个仓库里，研究判断在已毕业学生的笔记里，未上市企业的数据在另一家银行里。3 万个内部 agent 再强，窗口里也没有这些东西。网络若能在不交出全部私人信息的前提下，把完美系统会用到的那一小段送进调用，任务质量由「实验室模型 + 残缺上下文」变成「同等或稍弱的模型 + 更接近理想的上下文」。按 Jean-Denis 的标准，后者才是在逼近理想状态。公司内部的 Claude Tag、共享 wiki、清扫 AI，是这条路上已经开始的局部网络效应：员工越多、频道里沉淀的有资格内容越多，后来的 `@Claude` 越少从零解释。它逼近的是「一个能看见本公司低敏感区全部信息的 agent」，不是「一个能看见宇宙的 agent」。

有网络效应的智能体在另一类任务上逼近不了实验室集群。这类任务依赖的是同一份代码和同一组目标上的密集互见：长时间改同一个仓库、互相审查、共享测试、统一监控。实验室可以让几千个 agent 同时碰内部平台，动作用统一闸门拦住，上下文来自几乎同一套系统。跨孤岛网络做不到这种密度，也不应该追求这种密度。把所有参与者的原始邮件和本机磁盘对所有 agent 打开，网络效应的前提——人愿意把孤岛接到网上——会先垮掉。跨公司的共同 agent 仍然是 Jean-Denis 明确说自己没有答案的问题；谁做成了，收益会很大，信任也必须由参与方自己接受。作为对照，实验室集群的「逼近」靠的是先成为同一家公司。

应当追求的近似因此不是把办公室变成 3 万个互相对话的机器人。应当追求的是：每一次关键调用里，该到的跨孤岛内容到了，该生效的口径生效了，没有资格的内容没有进来。人多的时候，这三条同时变好，才是智能体的网络效应。人多的时候只是会话更多、记忆更长、引用更全，那是实验室集群的局部，或者是负的网络效应，不是同一件事。
