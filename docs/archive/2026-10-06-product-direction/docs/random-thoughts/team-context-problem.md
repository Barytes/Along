本质上是一个搜索问题。在团队所有人的信息中，搜索出任务需要的、不涉及隐私的信息进入AI agent的上下文。
希望团队知道自己知道的信息，以及团队成员的Agent知道自己知道的信息。
将自己的信息传递给他人需要付出很多成本：
1）自己需要筛选合适分享的内容，包括不涉及隐私的、以及有利于当前任务的。
2）需要实际上去share这个动作，例如开会讨论、Google Drive传文件等等
3）组织信息很费脑筋。在个人电脑上是一大锅杂乱的信息浓汤，每个人组织信息的方式不一样，各种文件夹层级等等。共享文件夹的信息也很快会变成一大锅浓汤，包括写冲突、修改记录、方向分歧等等。单纯把所有内容堆在一起会导致更多的混乱。

上下文问题还是很依赖人类。
AI看到什么上下文、记下什么内容还是非常依赖人类来判断每一条到底有没有道理、有没有用。
功能上当然能够交给AI自动读写。但是很难保证读写的内容是正确的，以及这些内容、读写这些内容的准则不随时间漂移，导致失效。

## 到达问题

到达问题是：对当前任务有用的内容已经存在，但没有进入这次任务里正在工作的 agent，或者把这份内容送进这次调用的成本高于把这件事再做一遍。已经存在，指内容已经在某台电脑、某个仓库、某次组会、某份私人笔记，或某个已经离开的人那里成形。进入，指接收方的 agent 在发起这一次关键调用之前，已经能读到那一份内容。成本包括筛选哪些可以给对方看、实际完成传递、通知对方去取，以及把各人自己的材料整理成对方找得到的形态。上面的筛选、传递和组织，就是这个成本在日常里的三步。

到达问题在任务开始的那一刻表现出来。人已经决定要做一件事，agent 已经打开，应当被用到的那份内容还在另一处。当事人接着会自己再做一遍，去问知道的人，或先停下来完成筛选、传递、通知或导入，再让 agent 重新开始。

## 选用问题

选用问题是：对同一对象已经存在多份不一致的理解，这些理解能够被当前任务看见，但这一次该生效的是哪一份没有被确定下来。同一对象，指同一个指标、同一张表、同一个业务问题、同一条规则，或同一类下一步该看什么。能够被看见，指这些理解已经处在当前任务可以读取的位置。选错其中一份，agent 会按那一份错误的口径行动。把多份收成一份唯一说法，会去掉只在特定场景里有效的那一份，agent 会按不适用于这次任务的口径行动。

选用问题在 agent 已经拿到材料、开始生成答案的那一刻表现出来。这一次调用同时读到了多份对同一对象的理解。生成出来的结果看起来完整，也带有引用，但对当前这个对象不适用。纠正它需要人对照这几份口径，确定这一次该生效的那一份，或退回每个人只用自己那一份。

## 保真问题

保真问题是：内容已经被写下，并且可能已经被当前任务读到，但这份内容没有资格被当成当前任务的依据。没有资格，指下面三件里至少发生了一件：

- 写下来的事实或整理出来的摘要是错的，后续检查发现不了对错。
- 文件里留下了结论，做决定的人当时没有想明白动机、适用条件和失败情况，后来的人把这句完整的话当成已经想清楚的依据。
- 任务需要的是这一次、在这个情况下做出的判断。存下来的材料不能代替人重新读、重新判断；把这些材料送进上下文，只是把材料重新摆在面前。

保真问题在内容已经进入共享层、并开始被后来的 agent 当成事实使用之后表现出来。写入的当时往往看不出来。过了一段时间，没有人看过的条目最先变错；写得很确定的错误被引用，再被写进新的摘要；人不再读，只让模型继续写。这一次调用里往往只有这一份写得很确定的内容，检查也没有报错，后来的 agent 会把它用到更多任务里。上面关于每一条是否有道理、是否有用仍要人来判断，以及内容和读写准则会随时间漂移而失效，就是这个资格问题对产品的限制。

三类问题可以在同一次工作里接连出现，每一次失败只属于其中一类。内容还在当前这次调用读不到的地方，这次失败是到达。内容已经能被看见，这一次用错了该生效的那一份，这次失败是选用。内容已经被写成完整的一句或一页，但这句话是错的、当时没有想明白，或不能代替这一次的判断，这次失败是保真。到达要补的是位置，让这一次调用读到已经存在的那一份。选用要补的是身份，让这一次调用生效的是适用于眼前这个对象的那一份。保真要补的是资格，只有已经想清楚、能够判断对错、并且能够承担这次判断的内容，才被当成当前任务的依据。
