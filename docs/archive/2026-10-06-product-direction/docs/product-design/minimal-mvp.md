# 通过成员引用读取共享资料的最小 MVP

本次先验证一件事：用户在自己的工作 Agent 中 `@` 一位成员，能否依据该成员已有资料解决当前问题。完整产品目标和能力继续保留在 [PRD](prd.md)，这里仅定义第一条可运行流程。

## 使用流程

1. 群组中已有 A、B 两名成员，B 选择愿意向群组共享的 Markdown／纯文本资料，同步到共享空间。
2. A 在工作 Agent 输入 `@`，从群组成员列表选择 B 并提出问题。
3. A 的工作 Agent 通过 MCP 搜索并读取 B 的资料，取得来源、版本和引用片段。
4. A 的工作 Agent 在当前会话中生成回答，说明依据来自 B 的资料；B 的电脑可以关闭。
5. B 更新或撤回资料后，后续检索和读取使用当前有效资料。

## 必须实现

- 最小群组与成员身份、必要登录认证，以及真实工作 Agent 的接入。
- 输入 `@` 展示成员列表并形成稳定成员引用，不能用普通姓名文本或网页筛选替代。
- 资料按提供成员保存，支持选定目录内 Markdown／纯文本的同步、更新和撤回，展示基本同步状态。
- MCP 提供成员列表、指定成员资料搜索和读取；选择 B 后不自动改为全组检索。
- 返回可以核对的来源、版本和片段；资料不足时由工作 Agent 明确说明。
- 已撤回资料停止检索和读取，重复同步不能自行恢复共享。更新时不混用旧索引与新正文。

## 共享空间在本次 MVP 中的含义

本次共享空间是成员主动同步资料的保存位置，按提供成员区分归属，供群组成员的工作 Agent 按所选成员读取。它不要求先实现完整产品中的自动整理、共同知识维护或共享条目发布流程；完整领域文档中“共享空间”的长期设计继续保留。

成员明确选择愿意向群组提供的文件，共享内容可以被群组内其他成员的工作 Agent 阅读和用于回答。资料仍保留提供者和原始来源，回答由提问方 Agent 生成，不冒称提供成员本人作答。撤回不能收回已经进入其他成员会话或设备的副本。

## 实现边界

服务负责成员、同步资料、检索、版本和访问控制；回答生成由提问方自己的工作 Agent 及其模型环境承担。本次不实现响应 Agent、独立模型服务、Token 额度、求助队列、候选回答审批、会话自动求助授权、留言板和共享空间自动整理。这些功能在完整产品中的定位不因本次范围而删除。

基础技术沿用 HTTPS、远程 MCP／OAuth、TypeScript／Node.js、SQLite 和持久文件目录。先接入一个实际验证过的工作 Agent 宿主，桌面目录同步客户端支持 macOS 和 Windows，并在两个实际运行环境分别测试和验收；客户端形式按实现负担选择。HTTP／MCP、最小身份和测试成员随第一条接入流程搭建，不要求先完成全部管理功能。

账户恢复、完整管理员后台、其他桌面平台支持和自动备份运维不作为最早试用流程的前置。先用少量成员、少量主动共享资料完成真实使用，再根据反馈安排这些交付工作；面向持续运行的部署仍需另行验收维护能力。

## 验收

- A 在真实宿主输入 `@` 并选择 B，取得基于 B 资料的回答和准确引用。
- B 与 C 的资料包含相同关键词时，选择 B 只返回 B 的资料；未授权账户无法读取。
- B 关闭电脑后，已同步资料仍可读；更新和撤回后不继续提供失效版本。
- macOS 和 Windows 分别完成客户端安装或启动、身份认证、目录配置、新增与修改同步、删除与排除撤回、失败恢复的实际验收。
- 至少完成一次真实工作问题，由 A 判断资料是否有帮助，由 B 核对引用和含义。
