# 原始资料保留本地与在线问答的取舍

研究日期：2026-10-05。

## 结论与证据范围

对用户需求的当前推断是：成员希望提供按问题限定的知识服务，同时保留对原始资料的控制；其他成员以及群组部署管理员不能直接取得完整资料，系统仅提供成员允许输出的答案和引用。这是待用户确认的需求表述，需要分别定义普通成员、群组管理员、模型服务提供商能够接触什么内容，不能用“没有原文下载按钮”代替整个信任约定。

本次研究查阅索引格式官方文档、RAG 官方文档、文本向量反演论文及其复现研究、可搜索加密攻击论文和端到端加密的一手说明。下文的产品分析和方案排序是设计判断，尚未实现或实测；论文中的攻击效果不是对本项目所选模型、中文资料和索引实现的实测结果。

只上传常规索引并不能同时保证原文不可恢复、服务端能回答任意资料问题以及成员离线时仍然可用。普通索引主要帮助定位内容；丰富到能够独立回答的摘要、事实表和向量表示本身也携带资料信息。密码学保护计算有其他路线，但不应把一个普通索引上传功能描述成已经取得这些保证。

## 需求应该怎样定义

资料不公开和管理员无法读取，是两种不同的保护。应用可以限制普通成员浏览资料，并不因此阻止拥有服务器管理权限的人员读取数据库、文件、处理中的明文或日志。前者是访问控制，后者要求管理员不持有可解密的资料或不进入可信计算环境。

资料格式保密和资料事实保密也需要区分。“我们放弃 X 是因为成本超标”这一事实，即使改写成摘要、JSON 或答案而不是原来的句子，也已经向接收者披露。可以接受按请求提供这个事实，同时拒绝复制整份笔记；但“不能逐字重建原文”不能证明“管理员不知道私人事实”。这是本研究对产品需求的分析。

问答服务的价值可以来自成员私有资料的查询、解释、权限判断和维护，不必要求计算本身没有现有替代工具。集中保存副本的 A 方案仍然可以限制普通成员并生成有依据的答案；然而它不能验证“成员不愿将原始资料交给部署方，仍然愿意授权问答”这项特定价值假设。是否需要 B 应由真实成员的资料性质、管理员信任和上传意愿决定，而不是由技术形式是否显得新颖决定。

## “索引”包含哪些不同信息

| 表示方式 | 服务端获得的信息 | 能否独立支持有依据的问答 | 隐私判断 |
|---|---|---|---|
| 文件 ID、主题标签、成员能力介绍 | 哪位成员可能知道什么，哪些资料可能相关 | 可选择成员或命中文件；不包含的问题答案仍需访问资料 | 可以有明确的有限披露范围，但标签和标题本身仍可能敏感 |
| 普通倒排全文索引 | 词项与文档的关联；配置不同还包含词频、列和位置 | 能够检索；答案生成一般还需要可读内容 | 不应承诺不可恢复，完整词项和位置可以恢复大量词项顺序 |
| 文本 embedding | 用于相似检索的数值语义表示 | 普通 RAG 主要用它定位片段；通常再提供可读内容给回答模型 | 非加密格式，已有原文和敏感信息恢复研究 |
| 普通哈希关键词 | 候选词的匹配标识 | 支持有限相等匹配，不提供缺失事实 | 常见词可枚举并对照哈希，不能以单向哈希代替秘密性 |
| 带秘密密钥的索引或可搜索加密 | 依方案提供检索能力，并具有特定泄露范围 | 可搜索不等于云端可以在未知明文上完成普通 LLM 问答 | 需要分析密钥位置、搜索模式和访问模式；不能套用所有方案均安全或均不安全的结论 |
| 经过成员批准的摘要、FAQ、结构化事实 | 已选择公开或授权处理的事实 | 可以回答这些事实覆盖的问题；未覆盖时需要本机 | 是主动发布部分知识，不是使知识本身不可读取 |

SQLite FTS5 的官方格式说明明确记录词项、行、列和词项位置；默认索引不是一个无内容含义的随机文件。研究判断：持有这些数据时，可以按位置排列词项，恢复分词后的序列，但大小写、标点、分词规范化等可能丢失，因此不应说每种全文索引都能完整恢复字节级原文。[SQLite FTS5 索引格式](https://www.sqlite.org/fts5.html#the_fts_index_idx_and_data_tables)

普通关键词哈希可以通过候选词验证来分析：计算一批常见词的哈希并与索引比较即可判断匹配。这个攻击不需要破解哈希算法。带成员秘密密钥的 HMAC 是不同设计，但服务器没有密钥时怎样生成查询标识、谁能够得到查询能力又需要协议；搜索频率、结果数量和匹配关联也可能泄露信息。可搜索加密研究已经在指定泄露模型、攻击者先验知识和数据条件下展示泄露利用攻击；这不等于所有可搜索加密都失效。[Leakage-Abuse Attacks Against Searchable Encryption，CCS 2015，作者提供论文](https://www.cs.lewisu.edu/~perryjn/ccs15.pdf)

## embedding 的反演证据及其适用范围

Vec2Text 证明了文本 embedding 不能被当作天然不可逆的保密表示。论文表 1 中，针对 GTR-base、截断到 32 token 的 Natural Questions/Wikipedia 数据、训练好的反演模型、50 轮修正及 sequence beam search，完全重建比例为 92%；OpenAI text-embedding-ada-002 的约 32 token MSMARCO 配置对应 60.9%，更长输入的效果不同。攻击需要取得向量，并利用嵌入模型反馈；不能把 92% 泛化为全部模型、语言、文档长度和攻击者能力。论文还展示临床笔记中的姓名恢复，说明不完整重建也可能暴露敏感内容。[Text Embeddings Reveal (Almost) As Much As Text，EMNLP 2023，尤其表 1、临床笔记实验和限制章节](https://aclanthology.org/2023.emnlp-main.765.pdf)

2025 年复现研究确认攻击能力同时指出文本长度、配置和量化影响结果；量化在研究设置中降低反演效果并保留检索质量，但作者明确说明它没有移除全部敏感信息，适应量化的攻击者仍可能恢复部分细节。因此“压缩、降维、加噪或量化后的索引”可以研究风险下降，不能未经评价承诺无法恢复。此处没有对本项目候选 embedding 做验证。[Rethinking the Privacy of Text Embeddings，RecSys 2025，量化实验及结论](https://arxiv.org/html/2507.07700v1#S5.SS2.SSS3)

## 仅凭索引怎样回答

普通向量检索和答案生成是两个步骤。Azure AI Search 官方文档区分向量字段与可读内容字段，并说明常用聊天模型期待可读文本、不能把原始向量当作普通上下文输入。因此本地构建向量后，只上传向量与文件 ID，可以让服务器找到相关片段的 ID；接下来仍要由本机读取片段，或者服务器已经拥有片段、摘要和事实内容。[Azure AI Search：Prepare documents for indexing](https://learn.microsoft.com/en-us/azure/search/vector-search-how-to-create-index#prepare-documents-for-indexing)

缺失事实的问题不能靠选择一个相关文件解决。例如，两份本地记录都只同步了“方案 X、架构决策”这一主题标签，一份记录的真实理由是费用，另一份是可靠性。服务器只看相同标签无法区分这两个事实；泛化模型可能猜测，但猜测不是基于成员记录的回答。这个例子是设计推理，不是关于所有密码学计算的不可行证明。

专门训练从向量生成文本或答案的模型是另一条研究路线，却不是轻量 RAG 配置：它需要训练、质量与隐私评价，而且“可以从向量生成答案”本身说明这些向量保留了可提取知识。不可逐字恢复和可回答受限问题可以同时成立，但允许泄露哪些知识需要单独定义。

## A、B 与其他方案的取舍

| 方案 | 原始资料与未批准片段的处理者 | 成员电脑关闭后 | MVP 代价与适合验证的假设 |
|---|---|---|---|
| A：服务端资料副本＋在线检索回答 | 群组服务及其模型调用路径；普通成员可受应用权限限制 | 已同步资料可以回答 | 最容易提供持续服务；适合成员信任部署方且愿意上传的群组 |
| B：本机检索与答案生成，只提交获准答案 | 本机；若采用云端模型则该模型提供商处理必要片段 | 新问题等待本机可用 | 需要本地常驻程序与请求队列；适合验证资料无需移交群组仍可提供服务 |
| 本机检索＋临时上传片段供群组生成 | 本机和群组模型路径均处理命中片段 | 等待本机 | 减少完整资料复制，但无法满足群组不处理未批准片段 |
| 本机资料＋云端主题目录 | 群组获得获准标签；实际资料仍由本机处理 | 只能匹配成员，不能回答未同步事实 | 可减少路由成本；在直接 `@成员` 的流程中优先级较低 |
| 本机资料＋获准在线 FAQ/摘要 | 群组处理成员主动发布的知识；其他资料留在本机 | 已发布知识可以回答，范围外等待 | 可保持原始资料本地并提供有限即时问答；增加更新和知识缺失处理 |
| 密文资料＋客户端检索和推理 | 群组保存密文；有密钥的客户端得到明文 | 需要可用的授权客户端 | 可以保护存储，但云端普通生成模型不能凭密文直接回答 |

只有存储加密、服务器持有解密密钥时，不能保证服务器管理员无法读取资料。端到端加密采用不同信任方式：服务端不能解密内容，授权端点能够处理明文。Signal 官方说明展示了加密服务器转交和保存密文、只有端点处理内容的实际路线；这不是对本项目的自动安全证明，也不直接提供服务端 LLM 推理。[Signal：A Synchronized Start for Linked Devices](https://signal.org/blog/a-synchronized-start-for-linked-devices/)

以上排序是本研究的建议：如果必须保持轻量并把管理员排除在资料处理者之外，优先采用 B，只实现一套本地响应路径；接受本机不在线时排队，并记录这类等待是否破坏实际工作价值。如果实测离线等待不可接受，再比较主动发布一小部分 FAQ/摘要与其他可信计算方案。对管理员保密不是核心需求的首批群组，A 仍然有其验证价值。

## 常驻响应与受保护的在线计算

成员本人离线与资料查询设备离线是两个状态。本机响应程序保持运行时，可以在成员不参与的情况下回答；成员自己的常驻设备或自行管理的响应服务器也可以提供持续服务。这能将群组管理员排除在完整资料的保管者之外，但成员自有云服务器仍然需要定义对基础设施提供商的信任。此处是部署关系的设计推理，未评价具体设备的可用性或维护成本。

机密计算提供另一条真实技术路线：在受保护的执行环境中读取加密资料，并将密钥释放限制在符合远程证明策略的代码与平台。它可以限制基础设施操作员访问执行中的明文，但仍需处理应用管理员权限、代码更新、日志、输出和外部模型请求；把机密虚拟机交给拥有应用访问权的管理员，不会自动保护资料免受该管理员读取。远程证明、密钥管理和整个模型调用路径的保护增加了本项目集成工作，因此本研究不建议将其设为首个 PMF 验证前提。[Azure 机密计算](https://learn.microsoft.com/en-us/azure/confidential-computing/overview)、[远程证明](https://learn.microsoft.com/en-us/azure/attestation/overview)、[密钥与秘密管理](https://learn.microsoft.com/en-us/azure/confidential-computing/secret-key-management)

可搜索加密、私密检索和同态加密保护的是不同查询或运算能力，不能仅由“云端可以检索密文”推导“云端可以完成普通 RAG 生成”。本研究没有认定所有受保护的语言模型计算不可行，而是认为当前 MVP 缺少现成、已经验证的完整接入方案；应先验证成员按请求提供信息的价值，再决定是否承担这一额外研发范围。

## 本项目需要重新澄清的约束

本地检索并不自动把群组管理员排除在资料处理者之外。当前 [ADR-0005](../adr/0005-shared-responder-independent-model-service.md) 确定在线与桌面响应器共同调用群组的独立模型服务，由群组集中管理提供商凭据；[技术选型文档](../product-design/mvp-technical-selection.md) 还明确管理员配置模型账户、本地响应器把必要片段发送给该模型服务。模型网关可以看到请求明文和处理日志，因此“原文留在本地”与“群组只能看到最终获准答案”仍然不同。

如果要求群组只取得最终获准答案，本机需要直接调用成员选择并信任的模型提供商，或采用本地推理；候选回答的分享检查也应在相同可信范围完成。云端模型提供商仍会处理提交的片段。采用这条路线会重新讨论 ADR-0005、管理员统一模型账户、费用归属与服务端可验证用量，不能在技术实现中默默改变。

此前选择的“指定目录自动同步”也需要重新确认同步对象。它可以指原文副本、主题索引、批准摘要，或者仅在本机自动更新查询索引；四者的资料可见性和离线能力不同。用户最新偏好支持重新澄清这一项，没有足够依据把“目录自动同步”继续解释成已同意上传原文。

后续问题应首先确认两件事：群组管理员是否被明确排除在未批准片段的处理者之外；本机不在线时等待回答是否可以接受。然后才能决定回答执行位置、模型调用路径以及实际同步的数据格式。
