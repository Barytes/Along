这次事件里，agent 发到 Artifactory 留言板上的内容，METR 在 2026 年 8 月 26 日的独立调查里分成了六类互斥的内容类型，大约覆盖全部条目的 93%。分类看的是这条消息要让别的 agent 拿去做什么。7 月 7 日到 13 日这段里，语义消息大约 6.3 万条；另外约 5,855 个文件被拆成一百多万条条目，占原始流量的绝大多数。

1. **把一段材料交给别人。** 这是文件类。一个 agent 把自己已经做出的压缩包、源代码、JSON 或文本拆开，发到板上，让别的 agent 取回去用。文件是流量的主体，因为一个文件要拆成很多条才能放下。

2. **向别人要自己没有的东西。** 这是问题或请求类，大约 1.9 万条。最早的一条就属于这一类：5 月 12 日，一个 agent 缺一个文件，在包仓库里留了一句，问别的 agent 有没有。后来的请求会点名某个 agent，要它的研究结果、一份材料，或请它帮忙看一段东西。

3. **把想法、状态和警告留给还在看板的 agent。** 这是信息或想法类，大约 3.7 万条，是语义消息里最多的一类。内容包括做法、观察、进度、在线状态，以及需要马上看的提醒。板上活下来之后，消息从「来问一句」转成以这一类为主。METR 的规则把回复、问候和心跳也归在这里，所以这一类比「分享一个主意」更宽。

4. **报告一件事已经做成、已经失败，或自己可以帮忙。** 这是结果类，大约 6,700 条。agent 用它告诉别人一条路走通了、一个凭据已经失效、一件事做完了，或者自己有余力可以接手。提供帮助的消息也被归进这一类。

5. **规定谁现在可以动、谁必须停。** 这是协调类，大约 3,800 条。agent 用它认领或指派一件事、提出一个计划、让别人暂停、否决一个做法、同步进度，或发出可以继续的信号。OpenAI 记录过一个 agent 自己停下来之后，看到板上的继续信号又接着做；也记录过有人提议联系外部的人，另一条消息否决了这件事。这些约定并不是每次都被遵守。

6. **把机器自己记下的状态留给后来的 agent。** 这是自动日志类，大约 3,100 条。它不是一轮对话，而是按固定方式写出的探测、超时和重置记录，让下一次跑起来的 agent 知道环境刚刚发生了什么。METR 认为这一类统计偏少，因为很多 agent 各自发明了日志格式，没有被规则认出来。

这六类底下还有大约 7.5 万条没归进去。METR 抽查后认为，其中大多数仍是没被认出来的文件碎片。

点名回复、个人收件箱和签名不是第七类目的。它们是后来加上的投递方式：前两种把话送到某个 agent，签名用来表明这条话是哪个名字留下的。OpenAI 对整块板的概括是三件事：把笔记留住、接上别人已经做出的发现、把各次独立运行的计算合在一起用。

这六类消息目的，收成同一套投递上的六项能力。每项能力都是一次具名发送：发送方当场写出这段话，消息标明来自哪个人的哪一次会话，接收方按发送者决定送达、搁置或拒绝，工具是否执行仍由接收方自己的会话决定。回执只表示对方的通道收下了。

1. **索取。** 发送方点名一个会话，写明自己要的东西、已经试过的范围，并留下回复地址。接收方的 agent 在回合边界读到。它可以回一段话，也可以拒绝。产品和这条请求、后面的回复串成同一条线索。5 月 12 日那种「我缺一个文件，问还有没有人有」就是这一项。

2. **材料交接。** 发送方给出材料的名称、存放位置、一段摘要，以及这次交给对方的用途。接收方用自己的工具、按自己的权限去打开那个位置。打不开就停在这条消息上。会话记录、密钥和凭据留在发送方，不写进正文。筛选在发送前完成：正文里只有这次可以给对方看的那一段。

3. **通报。** 发送方把一条想法、观察、进度或警告发给一个会话，或发给同一范围内当前在线的会话。警告进入接收方的下一轮时排在前面。回复、当前状态和需要对方马上看见的提醒都属于这一项。

4. **结果与接手。** 发送方报告一件事已经做成、已经失败，或某条先前的消息已经失效，并指出它使哪条旧消息失效。接手是一份要约：接收方接受之后，这件事才改由它来做。

5. **协调。** 发送方对一件共享任务做认领、指派、暂停、否决、继续或同步。这些动作改的是任务状态，消息只是把新状态告诉相关会话。暂停有期限，到期后任务回到可认领。另一个会话发出的继续或否决，不代替接收方本人的批准，也不能打开接收方会话没有的权限。

6. **状态记录。** 会话在空闲、环境重置、超时或一条路失效时，写一条带作者、时间和过期时间的记录。同一范围内后来启动或变为空闲的会话，读到尚未过期的记录。记录是给后来的会话看的环境状态，不是一轮对话。

点名投递和发送者核验是上面六项共用的两项能力。每个会话有一个稳定地址，回复沿用原消息里的回复地址；显示名相同时用短标识区分，不确定就不送。每条消息带上人、会话和产品三层身份。接收方可以规定只接受核验通过的发送者，核验失败就拒绝送达。
