# Along 兴趣小组场景与产品定义

更新日期：2026-10-06。

项目开发遵循 [项目开发约束](project-constraints.md)：实现 idea 并积累求职成果，控制持续运营投入，方便用户自行部署，并尽量与通讯产品及 Enterprise AI context 产品保持正交。

Along 是面向兴趣小组的共同探索与协作空间，成员通过个人主页、问答和围绕内容的讨论了解彼此，并自愿建立共同项目。成员可以接入自己的工作 Agent，也可以直接提交材料，由产品帮助整理主页和问答资料。产品帮助成员了解彼此正在做什么、经历过什么、为什么形成某种判断，让分散在个人工作过程中的经验成为交流、启发和自愿合作的依据。

产品的核心目标是促成更多有意义的人与人之间的连接。个人主页让成员发现值得了解的人，成员问答服务让了解可以异步发生；当部分成员决定共同开展一件事时，产品支持他们汇总获准材料，形成项目共享及具体产物。

## 兴趣小组的场景

目标用户是一群关注同一方向、各自开展相关但不完全相同活动的人。小组可以围绕 AI 产品、独立开发、研究、创作或其他共同兴趣形成；成员可能正在开发同一个项目，也可能各自探索不同项目。成员背景可以包括技术和非技术领域，彼此的熟悉程度也不相同。

部分小组成员使用不同的 AI Agent 处理自己的工作，例如 Codex、Claude Code 和 OpenClaw，其他成员可以直接提供自己的记录和产物。成员积累的材料包括工作记录、尝试与失败的过程、判断理由、项目产物和对外部信息的理解。这些材料可能包含可分享的一手经验，但平时主要留在各自的工作环境中。

小组主要通过微信群等已有渠道交流，很难持续了解每个人最近的思路。会议需要协调共同时间，逐个约 coffee chat 也有时间成本；不熟悉的成员缺少具体话题时，很难主动开始交流。群聊里已有其他话题时，分享新经验需要重新组织表达、切换讨论主题，并承担主动开口的社交摩擦。

小组缺少自然的经验整理过程。偶尔大家讨论出认可的内容，通常依靠记忆或某位成员自觉整理；固定周报会把兴趣交流变成额外义务。GitHub 对部分非技术成员有使用门槛，小组也不愿为了交流统一迁移到飞书、Discord 或其他社交软件。

这个场景来自产品发起者对自身需求的描述，是当前产品设计的起点。其他兴趣小组是否有相同需求，以及成员是否愿意持续授权材料，需要通过实际试用确认。

## 希望服务的需求与分享动机

产品同时服务三类需求：发现值得交流的人和具体话题；了解已知成员的近期工作、经历和判断；借鉴其他成员的经验，推进自己的事情。成员可以从浏览群组近期探索开始，也可以直接访问已知成员的主页，或带着具体问题寻找相关成员与材料；进一步交流和共同项目由成员自愿发起。

产品发起者自身的分享动机包括以下四项：

- 让相关的人了解自己正在探索的问题，并带来具体交流或反馈。
- 扩大自己的影响力。
- 出于利他意愿，希望自己的工作能够帮助他人。
- 在交流中发现新奇的想法，并开展新的、有趣的项目。

这些动机来自发起者的个人偏好，不代表所有成员都有相同动机。其他成员的参与动机、愿意提供的材料和期待获得的回应，仍需通过具体经历及试用了解。

## 发起者提供的具体经历

以下经历由产品发起者在需求讨论中自述，用于澄清需求，不代表其他当事人已经表达参与意愿。

- 发起者使用过 Superlinear Academy 创始人开放的 ask.lizheng.ai 问答服务，认为结合其访谈资料解答自身疑惑很有用。
- 发起者阅读一篇介绍 Sigil Wen 的文章后，希望学习他主动走进市场、创造机会的技能，但不知道如何开始。
- 发起者几个月前在 Superlinear Academy 社区回答过 Joey Wu 的一个问题，如今希望了解该问题是否解决及解决方法，但不太敢直接询问最新进展。
- 发起者与研究生舍友谈到学习 Agent，得知舍友的对象也希望转行到 Agent 方向。发起者认为可以组成学习小组，但后续没有推进；对方忙于现有工作是发起者提出的可能原因。

这些经历分别涉及借鉴具体人物的经验、将启发转化为自身行动、了解熟人的最新进展，以及围绕共同兴趣开展活动。产品通过获准材料和异步问答支持经验获取，通过成员更新提供近况，通过项目空间支持自愿协作。材料是否包含所需经验、成员是否愿意更新和参与，仍需要实际试用验证。

## 产品提供什么

### 群组与成员 Agent

群组是兴趣小组在产品中的成员集合，连接每位成员及其选择授权接入的 Agent。核心加入方式是由已有联系的小组建立空间并邀请成员，成员不必彼此熟悉。成员身份独立于 Agent 品牌；成员更换 Agent 后，其个人主页、分享范围和参与关系仍然属于本人。

群组以成员之间的共同探索为主要关系：成员围绕相近兴趣开展各自的事情，每个人都可以分享经验、提出问题、了解其他成员或发起项目，参与程度可以不同。群组应在没有知名人物或少数持续高产分享者的情况下仍具有使用价值。

产品保留群组作为核心形态，帮助成员形成集体归属感、建立更深入且持续的人际联系，并让部分成员能够快速开始新项目。独立的个人公开主页与问答服务保留为后续扩展，方向包括让成员一键将自己的主页和问答服务发布或部署到公开网站；公开发布需要遵循相应受众的分享授权。

产品允许成员沿用各自使用的 Agent，并提供人可以直接浏览的成员与项目页面。成员可以从群组中发现彼此，通过自己的 Agent 发起查询，也可以从成员页面进入问答。非技术成员参与时应能完成加入、浏览、提问和选择材料等基本操作，无需学习 GitHub 或维护服务器。

接入工作 Agent 不是成员参与的前提。未接入 Agent 的成员可以通过网页浏览和使用其他成员的问答服务、手动提供材料与成果、参与项目讨论及共同确认。产品提供材料整理能力：成员主动上传、粘贴或填写材料后，产品帮助整理和筛选，生成个人主页草稿及详细问答材料，供成员检查、修改和发布；后续可以通过提交新材料更新。

群组首页以成员近期的探索为主要内容，包括正在开展的工作、新尝试、遇到的问题及项目参与邀请。每条内容可以进入对应成员的主页或问答，内容来自成员已授权发布的材料，由工作 Agent 或产品的材料整理能力协助准备，不要求成员另外撰写动态。产品同时保留成员主页列表和提问入口。

人与 Agent 的共同讨论围绕具体内容和项目展开。成员可以讨论某条探索、向成员问答服务提问，或在项目内提出任务、查看 Agent 结果和共同确认取舍；讨论与对应内容或项目关联。日常通讯继续使用小组已有渠道。

### 个人主页

个人主页是依据成员获准材料整理、面向指定受众展示的介绍页面，可以由成员自己的工作 Agent 或产品的材料整理能力生成。主页说明成员近期正在做什么、关注哪些问题、做过哪些尝试，以及愿意分享哪些经验和教训，让其他成员能找到具体的交流话题。

主页的内容以可分享材料和成员主动填写的信息为依据，并展示资料来源或更新时间。成员能够预览、修改和撤回内容，在设定的分享规则内允许 Agent 持续更新。材料中的阶段性判断应保留背景，主页应让读者理解成员当前的探索，而不是将每次尝试都描述为稳定结论。

个人主页降低分享时重新组织表达的负担。成员选择或提交已有材料后，工作 Agent 或产品完成面向他人的整理；产品不要求成员按周提交报告，也不要求成员为了保持活跃不断发布新内容。

分享以 Agent 根据成员指定材料准备内容为主要方式，成员通过更新权限决定哪些变更需要确认、哪些可以自动发布，避免日常更新都要求重复确认。产品也支持成员在有内容想分享时主动要求 Agent 整理并发布。

已接入工作 Agent 的成员优先利用自己的 Agent 承担材料整理、筛选、主页编辑和更新等任务。产品提供的在线整理能力支持直接提交材料的成员，两种方式遵循相同的分享范围、筛选和发布确认规则。

首次分享一组材料时，成员检查准备发布的完整问答材料，并确认分享范围与筛选规则。后续在既定来源、受众和筛选规则内的日常进展可以按更新权限自动发布；新增材料来源、扩大分享受众或无法判断是否符合筛选规则的内容，需要成员再次确认。具体检查界面及规则表达方式仍需设计。

### 成员问答服务

成员问答服务独立于成员的工作 Agent，依据成员授权用于问答的详细材料回应其他成员的问题。工作 Agent 或产品的材料整理能力负责准备材料、筛除不愿分享的内容、润色和更新主页；问答服务负责使用已获准的材料提供回答。其他成员可以询问“你最近在研究什么”“你为什么放弃那个方案”“你在这个问题上有哪些实际经验”，逐步了解对方的工作和思路。

深入问答是产品的基本能力，能够使用获准材料中的经历、过程和判断依据，不局限于主页的简短介绍，也不要求成员另外开启一个深入问答选项。成员不愿分享的内容需要在准备问答材料时筛除。

本次讨论确认的初始筛选规则是保留产品思考和未解决的问题，对涉及他人的经历先去除身份，并删除没有依据的个人推测。对于发起者自身的求职目标和投入偏好，采用在相关交流中主动补充的方式，暂不进入群组问答材料；这一选择不代表所有成员都必须排除此类背景。

回答应说明依据来自哪些材料，保留经验发生的时间、背景和适用条件。材料不足时，Agent 说明自己无法回答的部分。Agent 对材料的整理和推断需要与成员本人明确表达的观点区分，问答授权也不包含替成员承诺合作或作出新的决定。

个人背景与需求可能随时间变化，产品需要区分历史经历和当前状态。过去表达的求职意愿、投入偏好或项目需求，不能仅因仍存在于材料中就被持续描述为当前事实。状态更新、过期信息的展示与回答规则仍需具体设计。

问答支持异步了解，减少为了获取基本背景而安排同步交流的需要。成员本人无需参与每次回答，其工作 Agent 离线时，问答服务仍应能够依据已经发布并获准用于问答的材料回答。问答结果可以帮助提问者形成更具体的交流话题，由成员自行决定是否通过原有渠道继续联系。

### 分享者反馈

产品应尽量让材料提供者收到正反馈，帮助形成互帮互助的氛围。即使提问者没有主动致谢、没有与提供者直接交流，提供者也应有机会知道自己的分享受到关注和使用。

向成员问答服务提问前，产品告知提问者：材料提供者可以看到提问者身份和问题。提供者先看到人数、主题等汇总，需要时展开具体问题与成员；普通问答采用汇总反馈，不逐条催促提供者处理。提问者明确希望本人回应时，单独发起联系请求。其他群组成员不会因此自动看到这段问答；在群组讨论中主动提出的问题，按讨论的可见范围展示。

产品支持整理常问问题列表，呈现反复受到关注或热门的问题，帮助成员了解受到关注的经验和可进一步交流的话题。列表的展示位置、受众、问题选取与更新方式在后续交互设计中确定，私人问答的展示仍遵循上述可见范围。提问人数和问题记录能够表明内容被使用；内容是否实际帮助了提问者，需要相应的效果反馈。

### 小组共同内容

小组共同内容是从成员获准分享的材料或讨论中整理、供指定小组成员持续查阅的内容。它可以记录某次讨论形成的共同判断、一个主题下的不同经验，或值得反复使用的实践记录。

Agent 可以帮助整理共同内容，减少对某位成员自觉整理的依赖。共同内容需要保留贡献者、来源和不同意见；多人材料中出现相似说法，不足以代表所有成员已经认可同一个结论。使用微信群讨论作为来源时，须由相关成员主动提供并授权，不以自动读取群聊为产品前提。

### 项目共享与共同产物

项目共享是部分成员自愿共同开展一件具体事情后，为该项目汇总的获准材料、共同记录和产物集合。项目参与者可以来自同一个兴趣小组，但无需要求全组加入，也无需将自己的全部个人材料提供给项目。

共同项目面向广泛的兴趣小组，产物类型保持开放，由参与者根据共同目标决定。例如，小说小组可以共同创作小说设定，AI 小组可以训练模型或开发基础设施，创业小组可以开发产品或编写商业企划书。实际工作继续使用成员已有的工具和执行环境；项目空间提供共享材料、协作和成果访问，适合直接保存的内容可以保存在项目空间，其他成果通过链接或接入方式访问。具体保存与展示方式仍需设计。

参与成员的 Agent 可以共同整理资料，并参与各自获得授权的项目工作。项目共享应让成员明确项目目标、参与者、材料来源和成果；具体对外发布、创建远程仓库及其他外部操作需要参与者授权。

产品方向包括让参与者在产品内开始共同工作：建立项目空间，汇总各自授权的材料，由 Agent 协助形成共同产物，并保存后续成果。参与者沿用各自的 Agent，让自己的 Agent 读取获准的项目材料、完成工作并将结果提供给项目空间。

成员授权后，各自的 Agent 可以直接协调项目工作，包括向其他成员的 Agent 提出请求、在已获授权的范围内处理请求并交付结果，需要成员决定时再请成员参与。项目空间需要呈现协作请求、任务状态和交付结果。具体工作分配方式及交付阶段仍需确定。

共同成果的整合按冲突对项目目标的影响处理。不改变既定项目目标和要求的局部冲突，可以由 Agent 在授权范围内自动协商整合；涉及影响项目目标实现的取舍，需要向所有项目参与成员说明分歧与影响，并取得每位参与成员的明确同意。未回复保持为尚未确认，有成员反对或尚未确认时保留原方案，Agent 可以继续处理不依赖该决定的工作。影响程度的具体判断依据仍需设计。

成员按项目授予自己的 Agent 持续有效的工作权限，规定允许承担的工作、使用的材料和资源，以及需要成员确认的事项。成员可以调整或暂停授权，授权范围内的正常协作无需逐条请求成员批准。

来自其他成员或 Agent 的协作请求必须接受接收方的权限检查，请求本身不授予权限，也不能修改接收成员的项目授权。项目成员身份不意味着可以指挥对方 Agent 使用项目外的私人材料、工具或资源。产品需要防止请求正文及附带材料中的恶意指令导致越权；权限执行与隔离机制、异常请求处理方式及安全验证仍需专门设计。

个人了解与共同项目之间存在自然的使用顺序。成员先发现彼此的兴趣和经历，通过问答判断是否值得进一步交流，再自愿决定共同开展项目。产品同时支持已有合作意向的小组直接建立项目共享。

## 一次完整的使用过程

以下过程展示产品希望支持的体验，以一个 AI 产品兴趣小组为例。

1. A、B、C 加入同一个群组，分别使用 Codex、Claude Code 和 OpenClaw。A 与 B 熟悉，C 与其他成员还不熟悉。
2. B 选择本地的产品实验记录、失败复盘和设计笔记，指定这些材料可以向群组分享。B 的 Agent 生成个人主页，展示 B 最近在探索的问题和可询问的经验。
3. C 浏览群组成员的主页，发现 B 做过与自己相关的尝试。C 通过 B 的成员问答服务询问：“你为什么停止了那个实验？我现在的条件是否适合继续尝试？”
4. 问答服务依据 B 已经发布并获准用于问答的记录回答，说明当时的约束、实际观察及仍未解决的问题。C 因此对 B 的思路有了具体了解，并在原有交流渠道中开始更有内容的对话。
5. B 与 C 决定一起做一个小项目，为该项目分别提供材料。两人的 Agent 汇总形成项目共享，并协助编译项目文档、landing page 或仓库内容。
6. A 可以浏览两人允许向小组展示的项目成果，获得新的启发，是否加入后续工作由 A 自己决定。

## 成员控制与参与原则

成员始终决定哪些材料可以被使用、向谁分享以及允许 Agent 做哪些事情。选择材料用于问答、将材料内容展示在主页、纳入项目共享和发布到公开网页，是不同的使用范围；个人主页也不因名称中包含“主页”而默认对互联网公开。

参与兴趣小组应当具有低负担和自愿性。成员可以只浏览、只提问、暂停分享或退出项目；产品不设置固定周报、强制发言、阅读确认和全员参与项目的义务。成员退出或调整分享范围后，产品应清楚说明哪些后续访问停止，以及哪些已分享的内容仍被保留。

成员撤回原始材料后，停止该材料的后续访问和问答使用，并更新相关主页内容。已经交付的回答作为历史记录保留，已经确认纳入项目的共同成果继续保留；成员可以停止后续贡献和自己的 Agent 执行权限。产品在成员分享或贡献材料时明确说明这些保留规则。具体删除流程、失效引用及历史记录展示在实施规格中细化。

成员使用不同 Agent 的能力需要通过实际接入验证。产品定义要求兼容不同成员的工具选择，但首批支持的宿主、材料格式和操作方式应由后续方案确定，不能仅凭品牌名称就认为已经完成兼容。

## 部署与服务承担

产品由小组中的部署者建立和维护实例，并邀请其他成员加入。部署者统一配置在线模型服务，承担在线材料整理和成员问答所需的服务费用，可以设置用量限制，费用如何分担由小组自行约定。普通成员无需各自配置模型账户即可使用这些在线能力。

已接入工作 Agent 的成员尽量使用自己的 Agent 完成材料整理、主页编辑及项目执行，相关费用沿用成员已有的工具与服务方式。在线问答服务持续使用获准材料提供回答，其可用性不依赖材料提供者的工作 Agent 是否运行。

## 产品范围与后续设计

当前产品定位是面向消费者的兴趣小组交流与连接。核心体验包括群组成员发现、依据已有材料生成个人主页、成员问答、自愿整理共同内容，以及部分成员形成项目共享。产品不以企业知识管理、组织统一口径、管理员分配工作和集中监督作为目标。

本文保留“授权材料、生成主页、了解成员、继续交流”作为第一阶段交付建议。项目空间及 Agent 协作属于已确定的产品方向；具体阶段、首批支持的宿主和实施规格另行确定，本次需求讨论不限定共同产物的类型。

产品以方便用户自行部署为交付方向，部署与维护的设计应符合项目开发约束。成员问答服务与工作 Agent 解耦、在线服务由部署者统一配置、工作 Agent 优先承担自身材料处理，是已确定的产品要求。Agent 接入、权限执行与隔离、材料处理、问答部署及用量限制的具体方案仍需设计。现有架构设计、技术决定和技术选型作为参考保留，输入 `@` 选择成员等具体交互方案需要按新场景评估。

## 产品价值的验证

产品是否有效，要看成员是否因此更了解具体的人，并产生值得继续的交流。试用应关注成员实际获得的新认识、提出的新问题、发起的后续联系和自愿形成的共同项目，同时记录准备材料和维护主页需要的投入。

早期试用可以围绕以下问题收集反馈：

- 成员是否愿意从已有材料中选择一部分用于分享，而无需额外撰写固定汇报？
- 主页是否帮助成员发现此前不了解的兴趣、经验或共同问题？
- 问答是否提供了具体、有依据、值得继续讨论的内容？
- 不熟悉的成员是否更容易开始有内容的交流？
- 技术与非技术成员是否都能完成基本参与流程？
- 部分成员是否自愿形成项目，并通过项目共享减少整理材料的负担？

主页数量、回答数量和 Agent 通信次数可以描述使用规模，但产品价值需要由成员的实际认识、交流与合作来判断。
